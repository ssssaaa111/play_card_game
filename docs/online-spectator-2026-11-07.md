# 只读观战验收 · 2026-11-07

## 本轮边界

- 独立 `watch.html`，不改玩家战场布局，不加载音频。桌面并排显示双方场地，窄屏上下排列；卡图和 ATK/DEF 独立布局，守备保持横置。
- 默认关闭。双方在准备前显式同意，准备后锁定，取消准备才可更改；同房再战和服务重启保留同意状态，旧版本存档默认关闭。开局后要撤销，需结束并退出原房间。
- 观众需现有账号登录、知道六位房间码，每房最多 20 个连接。没有公开房间列表、聊天、踢人或匿名观战。
- 服务端为观众单独投影：双方手牌、牌序、未发动陷阱、响应候选、私有卡组、账号 ID 和恢复令牌均不下发。已提交的连锁来源才公开。
- 观众连接不可提交对局或房间变更，即使伪造玩家身份、携带有效玩家令牌也会被拒绝；观众进出不占席位、不改版本、不暂停或重置玩家时钟。在线人数不写入持久化存档。
- 只同步当前场面及最近 40 条事件中的公开行动；不是从第一回合开始的完整复盘。断线保留并标记最后公开画面，自动重试失败后可手动重连；权限撤销或房间过期时清除画面。

## 自动检查

- `tests/online-spectator.test.mjs`：12 个确定性用例，覆盖授权、脱敏、已发动连锁、额外元数据白名单、人数限制、只读、计时不变、旧存档、重启和再战。
- `npm run smoke:online-restart -- --spectator`：隔离账号/端口/存档，真实 WebSocket，四次强制重启；包含未登录/未同意拒绝、权限撤销、伪造指令、隐藏信息与公开连锁、重启重入和再战。
- `spectator-layout-desktop/mobile/narrow/landscape`：仅本机 `test=1` 的公开样例，不访问真实房间；检查满场、99999 长数值、盖牌无详情、横置守备、详情按钮可达及无操作按钮。输出包含实际内容视口，不能把启动窗口尺寸当成手机视口。
- 沿用现有三个 CI 任务，只扩展现有联机冒烟和浏览器用例集。

## 真实页面验收

测试服务使用独立本机端口 5184、独立房间存档、`attack-chain-response` 固定起手及延长的回合计时。两名合成测试账号分别在内置浏览器和独立 Chrome 会话登录，第三页在内置浏览器只读观战。两个玩家页均确认音效关闭；观战页没有音频模块。

1. 双方未同意、只有一方同意时均拒绝进入；双方同意后可观看等待页。一方在未准备时撤销同意，观众立即收到关闭提示且场面被清除；重新同意后可进入。
2. 双方选择完整 56 张均衡与 50 张守护反制，准备后观众仅见起手数量 5/5、牌库 51/45，不见手牌名称。
3. 1P 盖放断链裁决、召唤日冕骑士；2P 盖放镜光反制、召唤铁壁守卫并转守备。观众看不到两张未发动盖牌名称，守卫横置且显示 900/2100。
4. 骑士攻击守卫，镜光反制提交 CL1 后才向观众公开；尚未发动的断链裁决仍隐藏。1P 发动 CL2 后原攻击继续，只造成一次 400 反击伤害：1P LP 3600、2P LP 4000，守卫战损后 ATK 750 / DEF 1950，双方陷阱入墓，骑士已行动。
5. 内置浏览器真实内容视口 320×720、390×844、844×390、1920×1080：确认无横向溢出，攻防数字不被卡图遮挡，守备横置，公开详情可打开和关闭。修复了窄屏卡片固有最小宽度造成的越界；桌面真实画面保存在本地 `.tmp/online-spectator-1107/desktop.png`，不提交截图。
6. 观众退出再进入、刷新不占玩家席位，玩家倒计时继续，人数正确恢复；三页同时打开时停止并重启同一路径的真实服务，观战明确显示“最后公开画面”，随后自动恢复同房、同 LP 与 750/1950 守备数值。
7. 1P 认输，观众显示 2P 获胜，无自动日志弹窗；双方同房再战，观众继续同步第 2 局、2P 先手及 0:1 比分。第 2 局以 2P 主动认输结束，观众比分正确变为 1:1。
8. 额外创建等待房间，在 390×844 实际勾选同意并准备，准备后复选框禁用；取消准备后解锁。844×390 时房间卡片内部可纵向滚动，准备/取消按钮可点击，无横向溢出。恢复普通视口并保留等待页。

这不代表所有卡牌、实体手机浏览器及生产部署均已验收；当前验证的是上述桌面浏览器中的真实交互、明确尺寸布局及确定性协议/规则回归。
