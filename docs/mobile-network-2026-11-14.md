# 手机与弱网恢复首轮 · 2026-11-14

本轮基于 `dbc8b23` 公开战报分支继续迭代。若主干尚未合入战报，建议先合战报，再合本轮。保持既有战场布局，不增加新的 CI job。

## 原因与修复

- WebSocket 原先没有握手时限；握手前只收到 close 时 Promise 不会完成。现在握手最多等待 8 秒，早关/报错立即释放，可重新连接。
- 原先主动断开不立即拒绝等待请求，旧 socket 的 message 也未绑定当前连接。现在断开释放全部等待，只接受当前 socket 的消息；同一房间低版本视图及迟到确认不能让画面倒退。
- 请求最多等待 8 秒。超时表示结果未能确认，而不等于行动未执行：关闭可疑连接、清理待执行界面，恢复原身份后读取最新状态；不自动重发指令。恢复成功清除旧超时提示。账号身份变化或会话失效停止自动恢复，不循环冒用旧席位。
- 登录服务的请求及响应体读取最多等待 10 秒，超时会中止请求；迟到结果不再改变账号状态。不自动重复登录或注册。
- 前台恢复、网络恢复、页面恢复和浏览器 freeze/resume 会触发同步；核对时锁住旧操作、取消结束回合确认，历史演出不补播。仅隐藏页面不主动断开席位；后台收到的战况仍更新，但不排队播放过时行动提示。
- 可见页面每 15 秒做一次只读心跳；服务端也每 15 秒发送 WebSocket 控制心跳，连续缺少应答的连接约在 15–30 秒内被清理，随后才进入原有断线保护。健康后台浏览器可由网络层回应控制帧，不因 JS 定时器节流就立即被当作退出。
- 不再把本地断网写成“对局已安全暂停”。本地只能锁住操作，服务端是否暂停、超时或已经结束，均以重新同步结果为准。
- 触摸拖动门槛从 6px 提高至 12px，鼠标不变；页面隐藏会清理进行中的拖牌，非主触点不发起拖动。未改为新的滑牌或长按交互。
- 观战恢复保留只读身份，明确标记最后公开画面；战报请求失联后禁用无效读取，恢复后可主动刷新，不自动跳页或改动历史滚动位置。

## 自动回归

- `online-network.test.mjs` 14 项确定性测试，使用手动时钟和事件目标，不依赖随机等待；覆盖上述超时、消息隔离、低版本保护、登录/响应体卡住、前后台/离线/冻结、心跳与触摸取消。
- 完整旧浏览器集合复现了鼠标拖牌被非主触点判断误伤的问题：保护现仅针对真实触摸输入，保留鼠标/辅助输入兼容，并补判断回归；`hand-reorder-basic` 复测通过。浏览器冒烟失败会额外输出简短 GitHub 检查注释，原断言与失败条件不变，便于在无日志下载权限时定位问题。
- `smoke:online-restart -- --spectator --network`：原有四次真实强制重启与隐私/再战检查继续保留；新增丢确认场景，验证服务端已提交的 END_TURN 恢复后只执行一次，客户端等待集合清空。
- 既有三浏览器 CI 使用真实浏览器生命周期冻结/恢复，确认前台校准后 LP 不变且不重播攻击；继续保留原来的手机布局、响应、再战和战报检查。没有增加新 job。
- 联机浏览器用例在恢复桌面视口后等待实际布局，再定位点击，并确认战报确实关闭后才验证退出观战；保留真实命中检查。点击超时会报告控件状态、遮挡元素和未关闭弹窗，避免只有笼统超时而无法定位。
- 普通浏览器回归失败（包括浏览器进程超时）也保存已捕获的 DOM、浏览器错误输出和失败摘要，随原任务上传附件；空 DOM 仍按失败处理，不增加自动重试，也不延长原有超时。

## 内置浏览器静音实测

独立本机服务 5188、转发器 5190、独立房间存档和合成账号；不修改系统网络设置，不影响默认玩家房间。

1. 实际召唤日冕骑士、进入战斗，确认音效关闭；对方 LP 4000。
2. 转发器保持连接且正常向服务器转发攻击，但吞掉所有返回消息。页面先显示“结算中”；8 秒后不再无限等待，显示结果未能确认、不会自动重发，并禁用过时的结束回合操作。
3. 恢复转发后自动重连，原房间、原席位保持；对方 LP 2300，骑士已攻击，无攻击补播。最终公开战报只有一条 1700 伤害记录。
4. 转发器完全停止双向应用消息，观众读取战报失败后明确显示旧画面，读取按钮禁用；恢复后原观众重新加入，提示可刷新，成功读取到相同的唯一伤害记录。
5. 玩家离开页面后使用浏览器返回，同一战况正确恢复；这是导航/刷新恢复，不把它冒充成实体手机系统休眠验收。
6. 观众 390×844 / 320×720 及玩家 320×720 / 844×390 下检查恢复后的控件、攻防和滚动，无横向溢出；恢复普通视口，实际认输结束测试并保留战报页。
7. 另建不回应控制心跳的真实连接，约 29.6 秒被服务端关闭；合成玩家的健康连接继续保留。
