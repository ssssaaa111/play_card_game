# 联机服务重启续局

基于主线 `d3b72a5`，本轮不改卡牌强度、战场布局和守备横置规则。

## 保留范围

- 等待房间的席位、账号绑定、已选卡组、准备状态。
- 对局完整状态：原实例 ID、原手牌和牌序、场上效果、墓地、当前回合、事件记录、未结算攻击与连锁优先权。
- 最近 100 条已确认指令的回执，重启后重发同一指令不会再扣一次血。
- 系列胜场、局数、先手轮换及已经接受的再战请求。

默认文件为 `.data/online-rooms-<端口>.json`，使用 `DUEL_ROOM_STORE` 可更换路径。账号会话仍由 `DUEL_AUTH_STORE` 指定的文件保存；重启必须使用同一套账号与房间文件。旧版本从未写入磁盘的房间不能自动迁移。

## 计时与容错

每次成功变更先写临时文件并刷新，再替换正式存档，随后才发成功确认。运行中的回合/响应计时每秒保存检查点，强制结束进程最多可能回退约一个检查点间隔的计时，不会重做已经确认的游戏行动。正常退出再补存一次检查点。

恢复时所有连接句柄作废，原账号凭原令牌恢复席位。双方各获得新的断线宽限期（默认 60 秒，从服务恢复时起），不能把服务停机时长算作玩家离线；双方都在线后才恢复回合/响应的剩余计时。宽限期结束仍未恢复，按原规则判负或双方离线平局。超过 6 小时无活动的房间不再加载。

损坏、未知版本、状态不一致的存档会阻止启动，保留原文件，不静默生成空房间文件覆盖。写入失败时服务停止，避免继续确认无法保存的行动。

## 隐私边界

房间文件是服务端私有资料，包含双方隐藏手牌、牌序及重连令牌，不能放到公开静态资源目录或上传仓库。默认 `.data` 目录已被 Git 忽略；本地静态服务对隐藏目录、点文件及编码后的私有路径返回 403。客户端只收到原有席位专属视图，不会收到完整存档。

当前实现面向单进程本地服务，不能让多个服务实例同时写同一存档文件；它不是分布式数据库，也不承诺文件丢失、磁盘故障或不兼容规则升级后的自动恢复。

## 验收

- 纯测试：等待房间、账号冒用拦截、手牌隐藏、牌序及事件完全保持、指令去重、旧版本拒绝、连锁剩余 3 秒恢复、重连宽限、系列战绩、再战、过期、损坏文件、写入失败和快照隔离。
- `npm run smoke:online-restart`：隔离真实服务中连续 4 次强制终止进程，覆盖准备、CL1 后的 CL2 响应、结算回执去重及再战恢复。
- 内置浏览器 + Chrome，双方音效关闭：同房使用 56/50 张卡组；盖断链裁决、召唤日冕骑士，另一方盖镜光反制；攻击后 CL1 加入、进入 CL2 窗口时重启服务，页面自动恢复原席位，剩余时间归零后 CL1 正常生效，不额外扣血。随后认输、接受再战，第 2 局 2P 先手；召唤铁壁守卫后再次重启，双方保持局数、0:1/1:0 战绩和原怪兽，恢复后可继续盖牌。
- 页面服务实测：正常页面与模块返回 200，`.data`、编码后的 `.data`、`.git`、`.tmp` 路径返回 403，未读取或输出私有文件内容。
