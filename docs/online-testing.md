# 联机迭代与回归

旧功能用确定性自动测试保底；每次新增可见交互仍要真实点击验证。浏览器发现的问题先修复，再把能独立表达的规则或交互状态加入单元测试。

## 快速回归

使用项目的 Node 24，运行 `npm run test:online`。不启动网络服务、不安装额外浏览器测试依赖，不使用随机等待。

## 每轮浏览器实测

1. 启动 `npm run serve` 与 `npm run serve:online`，分别用两个浏览器打开 `http://127.0.0.1:5177/online.html`，注册或登录不同账号后创建、加入并准备。同一浏览器共享当前登录账号，不能伪装成同房第二名玩家。验证观战时再用第三个已登录浏览器输入房间码并点击“只读观战”。
2. 优先走本轮新增流程，以及直接关联的取消、失败或重复点击分支。通过页面按钮和卡牌操作，不通过控制台直接调用业务函数或修改牌局来代替点击。
3. 对照另一玩家页面，确认账号、目标、LP、卡牌和回合一致；刷新确认 Cookie 仍保持账号且房间凭据恢复原席位。新增弹窗同时检查桌面与窄屏，按钮不遮挡、无横向溢出。
4. 记录实际动作、预期与结果、控制台错误、截图。新发现的问题若能用纯函数或固定牌局表达，就补进快速回归。

联机卡组验收：先在单人编辑器保存自定义卡组，回到等待房间刷新列表并选择；准备后选择器禁用，取消准备后解锁，刷新已准备页面仍恢复原选择。双方可分别选择 56 张自定义均衡卡组与 50 张守护反制，起手各 5 张后牌库分别为 51/45，而不是统一截成 35。完成一次实际召唤、刷新恢复、认输与同房再战；新局仍保留各自完整卡组，先手按原有规则轮换。检查对手页面和投影视图都没有收到另一方的私有卡组名称与构成。390×844 与 844×390 下检查选择器、刷新和准备按钮；横屏允许房间卡片内部滚动，但不得横向溢出。

观战验收：第三个浏览器中途加入时不占用 1P / 2P 席位，也不能让对局暂停；顶部观战人数应在加入、关闭和退出时实时增减。桌面允许切换“1P 视角 / 2P 视角”，切换后玩家名、墓地标题、恢复简报和结果标签都必须跟随主视角，刷新后仍保留选择。双方手牌区域不渲染，未翻开的双方陷阱只显示统一卡背。公开怪兽、魔法、墓地、生命值、回合计时、响应状态、连锁回放与战斗记录需要实时同步；观众页面不显示出牌、战斗、结束回合、认输、响应和再战入口。刷新后应显示“已恢复至观战现场”，仍保持只读；观众关闭或重连不得改变玩家连接状态、回合计时和房间结果。

结束页再战验收：一方点击“再来一局”后按钮进入等待态，另一方显示“接受再战”；双方确认后关闭结果弹窗、保留房间、身份及房间系列战绩，并由上一局后手方先手开始下一局。任一方断线时保留已确认状态，重连后继续。点击“查看残局”后，顶部必须保留“对局结果”入口，重新打开时焦点回到再战按钮；新局开始后恢复常规回合操作。身份区显示当前局数，结算页战绩按当前观看者显示为“我方胜场 : 对手胜场”。

操作闭环验收：手牌区右上角汇总“可行动”数量，包含可出手牌与可发起攻击的场上怪兽；连续点击会按顺序定位这些对象。手牌应明确显示推荐落点、唯一合法目标或多目标数量，双击可使用推荐落点直接出牌；场上可攻击怪兽双击会在需要时自动进入战斗阶段。键盘聚焦手牌后，首次 Enter/空格选择，操作完整时再次按键执行。房主与挑战者必须使用相同逻辑。

联机入口及本轮改动的模块使用同一版本参数，避免旧标签页混用缓存中的主模块、手牌渲染器、场地渲染器和交互投影。

回合收尾验收：顶部“进入战斗”显示当前可攻击怪兽数；存在手牌或攻击行动时，“结束回合”显示未行动总数。第一次点击只进入约 3.6 秒的红色确认态并在场地中央给出提示，第二次点击才交回合；确认超时、选择卡牌、状态版本变化或对手接管回合都会自动解除。没有剩余行动时保持一键结束，不额外弹窗。

整回合时限验收：开局与每次回合交接后，双方顶部显示同一个 90 秒服务端倒计时；普通出牌不会重置。最后 15 秒转为红色警示，归零后服务端自动结束当前回合，并在双方战斗记录中标记“回合超时”。攻击响应期间以及任一席位断线时冻结剩余时间，响应完成或双方恢复连接后继续。测试服务可用 `DUEL_TURN_TIMEOUT_MS` 缩短时限，最低 1000ms。

### 账号与登录态

- 账号和会话由对战服务保存到 `.data/online-auth.json`（可用 `DUEL_AUTH_STORE` 指向独立路径）；该目录不会进入版本控制。
- 密码使用带随机盐的 scrypt 摘要保存；浏览器只保存 30 天有效的 HttpOnly、SameSite=Lax 会话 Cookie，前端脚本无法读取会话令牌。
- 房间恢复令牌按账号 ID 写入浏览器本地存储。刷新、重开浏览器可恢复当前账号的牌局；退出登录会清理本浏览器当前账号的房间令牌。
- WebSocket 建连时从 Cookie 识别账号，创建、加入和恢复席位均以服务端账号昵称为准。重连令牌不能跨账号使用，同一账号不能同时占用同一房间的两个席位。
- 登录按“来源地址 + 账号”限制连续尝试，注册按来源地址限制频率；默认 10 分钟 8 次，超限返回明确的剩余等待秒数。可用 `DUEL_AUTH_ATTEMPT_LIMIT` 和 `DUEL_AUTH_WINDOW_MS` 调整。
- HTTP 登录接口和 WebSocket 升级使用同一来源白名单。浏览器从未配置的站点携带 Cookie 连接时会被拒绝；无 `Origin` 的本机冒烟客户端仍可运行。仅当服务绑定回环地址时自动允许其他本机端口。
- 对局中断线默认保留席位 60 秒，页面显示服务端截止时间的倒计时；到期仍未恢复时，在线方自动获胜。可用 `DUEL_DISCONNECT_GRACE_MS` 调整服务端时限，重连成功会立即取消判负定时器。
- 本地开发默认允许 `localhost` / `127.0.0.1` 的跨端口页面。部署时设置 `DUEL_ALLOWED_ORIGINS`，反向代理场景显式设置 `DUEL_TRUST_PROXY=1`，并在 HTTPS/WSS 后运行以获得 Secure Cookie。

本轮攻击预览验收：直击 1500，LP 3800 → 2300；守备反击 200，我方 LP 4400 → 4200；切换两个目标时预估伤害由 600 变为 100，最终仅结算选中目标。390×844 下确认按钮可见，取消无扣血，重复确认不重复结算。

## 检查范围

### 可重复的陷阱实测

本机单独启动 `node scripts/duel-server.mjs --port=5180 --scenario=trap-response`，双方打开 `http://127.0.0.1:5177/online.html?duelServer=ws%3A%2F%2F127.0.0.1%3A5180%2Fduel`。这只是服务启动参数，客户端不能指定起手牌；仅允许绑定本机地址，正常服务仍随机发牌。

- 1P 起手包含日冕骑士、疾风术士；2P 包含镜光反制、弱化力场、风暴转移、守护刻印。
- 1P 召唤骑士并结束回合；2P 盖放四张陷阱后结束；1P 召唤术士，进入战斗。
- 骑士直击：响应前 LP 保持 4000，1P 不能结束回合；2P 选择弱化力场，最终 LP 2800，骑士 ATK 1200。术士直击后刷新 2P，响应仍存在；放弃后 LP 1600，未发动陷阱仍盖放。
- 下一轮双击镜光反制破坏骑士，不追加伤害；术士直击发动守护刻印，重复确认仍只抽一张且 LP 不变；再下一轮仅剩风暴转移时自动选中，发动后 LP 2000，原攻击取消。
- 不操作响应窗时，15 秒后自动按放弃响应结算且只结算一次；响应中断线会冻结剩余秒数，恢复原席位后继续倒计时。
- 召唤响应验收：1P 盖放「召雷陷阵」并结束回合；2P 普通召唤后双方操作冻结，1P 显示青色 `SUMMON RESPONSE` 弹窗且唯一候选自动选中，2P 显示等待响应。发动后陷阱进入墓地、2P 仅受到一次 400 伤害；放弃或 15 秒超时则不造成伤害，召唤怪兽保持在场。响应期间整回合计时暂停，断线重连继续剩余响应时间。
- 召唤反制连锁验收：用 `--scenario=chain-response` 启动固定场景；1P 盖放「召雷陷阵」，2P 盖放「断链裁决」后召唤「赤焰幼龙」。1P 发动后，2P 显示粉色 `CHAIN RESPONSE`、新的 15 秒倒计时、CL1/CL2 卡牌和 `CL2 → CL1` 结算顺序。2P 发动 CL2 后两张陷阱各自入墓，召雷陷阵不造成 400 伤害；放弃或超时则只结算一次 CL1。响应关闭后恢复原回合剩余时间。
- 攻击反制连锁验收：用 `--scenario=attack-chain-response` 启动固定场景；1P 盖放「断链裁决」并召唤「日冕骑士」，2P 盖放「镜光反制」。下一轮日冕骑士发起攻击，2P 将镜光反制加入 CL1 后，1P 获得新的 15 秒响应并可加入 CL2。发动断链裁决后，镜光反制标记为未生效、双方陷阱各自入墓，日冕骑士保留在场并继续完成原攻击；放弃或超时则由镜光反制破坏攻击怪兽且不追加战斗伤害。
- 多段反制连锁验收：用 `--scenario=multi-chain-response` 启动固定场景；1P 盖放两张「断链裁决」并召唤「日冕骑士」，2P 盖放「镜光反制」和「断链裁决」。下一轮由日冕骑士发起攻击，依次加入镜光反制 CL1、1P 断链裁决 CL2、2P 断链裁决 CL3、1P 第二张断链裁决 CL4。每次优先权交接都应获得新的 15 秒，弹窗底部操作按钮在 CL4 时仍固定可见；结算顺序显示 `CL4 → CL3 → CL2 → CL1`，最终 CL4 与 CL2 生效、CL3 与 CL1 失效，原攻击继续并造成 1700 伤害。
- 连锁结算演出验收：发动 CL4 后响应弹窗必须先关闭，再由独立回放层按 `CL4 → CL3 → CL2 → CL1` 逐张亮起。生效卡保留彩色高亮，被无效卡灰化并盖「无效」标记，同时写明由哪一段无效；底部汇总 `CL4、CL2 生效 · CL3、CL1 被无效` 以及《日冕骑士》直接攻击的 1700 伤害。演出期间棋盘不可误操作，结束后恢复操作；战斗记录应同时保留连锁摘要和最终战斗结果。
- 本轮桌面、390×844、844×390 均实际点击通过；响应弹窗无横向溢出，双方浏览器无警告/错误日志。

`npm run smoke:online -- --scenario=trap-response` 连接同一固定场景服务，验证真实 WebSocket 上的盖放隐藏 → 攻击暂停 → 防守方断线重连 → 发动破坏陷阱 → 认输 → 双方同房再战。CI 已使用此场景；普通 `npm run smoke:online` 仍可验证随机牌局，不再假定起手必然有可召唤怪兽。

`npm run smoke:online -- --custom-decks` 使用同一服务，补验完整自定义卡组/预设、非法卡组不改房间、准备锁定、私有选择不外泄、断线重连与再战构成保持。现有联机 CI 步骤会依次运行这两种冒烟，不新增独立任务。测试固定起手牌必须已经存在于选定卡组中，服务端不得为显式卡组悄悄补牌。

`npm run smoke:online-restart` 自行启动隔离端口、独立账号文件与房间文件，不操作已经运行的开发服务；连续 4 次强制结束真实服务进程，分别验证准备/卡组、未结算连锁、已结算指令去重和已确认的同房再战。它已加入现有联机 CI 步骤，不增加任务。真实页面验收还需让两个账号保持打开，停服后确认暂停状态，重启同一路径的服务，观察自动重连及战况摘要，并实际继续操作；只刷新页面不能替代服务进程重启。

`npm run smoke:online-restart -- --spectator` 在上述隔离流程中增加第三条真实观战连接：未登录、默认关闭、单方同意均不得进入；双方同意后收到双侧脱敏视图，伪造玩家身份或重连令牌也不能提交指令。每次重启重新加入观战，验证权限保留而观众连接不持久化，连锁只在发动后公开，退出不改房间版本或玩家时钟。现有联机 CI 使用此扩展模式，不新增任务。

观战页面实测需保留两个玩家页面和一个 `watch.html` 页面，通过实际操作完成双方同意、准备、盖牌、召唤、表示切换、攻击反制、观众刷新/退出/重连、停服恢复、认输与同房再战；全程静音。手机宽度 320/390 和横屏都要通过浏览器明确设置视口后检查，不能仅依赖无头 Chrome 的窗口参数（某些 Windows 版本最小内容宽度仍为 500）。`spectator-layout-*` 四项冒烟只验证明确标记的本地公开布局样例，覆盖满场卡槽、横置守备、长数字及详情关闭，不代替真实账号、权限和网络同步验收。

`npm run smoke:online-browser` 使用两个独立 Chromium 进程和两套隔离 Cookie，真实点击固定陷阱场景。它会验证“双重召唤”演出不会被随后的召唤覆盖、日冕骑士双击攻击、弱化力场响应、双方最终 2800 LP、战报中的 1200 伤害，并在 `.tmp/online-browser-smoke/` 保存命中伤害演出瞬间的 PNG 与完整演出序列 JSON。运行前分别启动前端 `127.0.0.1:5221` 和带 `--scenario=trap-response` 的对战服务 `127.0.0.1:5223`；端口不同时可传 `--frontend-url` 与 `--duel-server-url`。

GitHub Actions 的 `online-browser-smoke` job 会自行启动前端与固定场景对战服务并运行同一条回归。每次运行都会上传 `.tmp/online-browser-smoke/`、前端日志和对战服务日志；即使测试失败，脚本也会写入 `online-browser-failure.json` 与 1P / 2P 现场截图，可从 workflow artifact 查看当时的回合、阶段、弹窗、手牌摘要和演出历史。

账号安全冒烟：以较小的 `DUEL_AUTH_ATTEMPT_LIMIT` 启动独立服务后运行 `npm run smoke:online-security`。它会验证未授权 HTTP 来源和 WebSocket 来源均返回 403、连续错误密码返回 429 与 `Retry-After`，同时确认允许来源仍能携带有效 Cookie 建立对局连接。

当前攻击与普通/祭品召唤响应都支持双方交替追加多段反制连锁，连锁长度由双方已盖放且合法的陷阱数量自然限制。对手断线时保留响应并冻结倒计时，重连后继续，不会在离线期间静默代替玩家放弃。

重连战况恢复验收：在对局已有公开行动后刷新任一玩家页面，恢复成功时必须只出现一次“已恢复至当前战况”摘要，显示双方当前 LP、回合归属、阶段、响应窗口状态与最近关键行动；历史动作不得重新触发攻击、召唤或连锁演出。摘要可以关闭、打开完整战报；存在已完成连锁时，摘要和顶部“连锁回放”均可重新播放最近一次连锁，且连续两次连锁不能串用上一段的卡牌或结算顺序。

### 提交前检查

- 日常小步修改：跑相关 UT 和 `npm run test:online`，实际点击新增交互。
- 提交前：跑一次 `npm test`。变更影响传输或房间服务时再跑 `npm run smoke:online`。
- 规则或人机共用组件变更：补跑关联规则测试及已有浏览器回归场景。
- 所有 UT 已纳入现有 CI 的 `npm test`；不必为每个既有用例重复打开浏览器，也不要用只匹配源码字符串的断言代替行为测试。
