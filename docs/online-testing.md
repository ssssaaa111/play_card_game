# 联机迭代与回归

旧功能用确定性自动测试保底；每次新增可见交互仍要真实点击验证。浏览器发现的问题先修复，再把能独立表达的规则或交互状态加入单元测试。

## 快速回归

使用项目的 Node 24，运行 `npm run test:online`。不启动网络服务、不安装额外浏览器测试依赖，不使用随机等待。

| 层次 | 自动覆盖 | 文件 |
| --- | --- | --- |
| 协议与权限 | 命令白名单、席位绑定、隐藏手牌和牌序 | `duel-command`、`duel-view` 测试 |
| 房间 | 准备、回合交接、重复命令、旧版本、重连 | `duel-room` 测试 |
| 选择与展示 | 稳定卡牌 ID、取消、目标切换、落点、祭品、攻击预览 | `online-duel-ui` 测试 |
| 异步交互 | 请求中不重复提交、失败释放锁、双击不穿透面板 | `online-action-runner` 测试 |
| 固定牌局 | 指定落点 → 强化 → 对手守备与第二次召唤 → 多目标攻击 → 双方同步 | `online-regression` 测试 |
| 攻击响应 | 仅被攻击方可操作、隐藏候选、放弃、各陷阱结算、重连、重复命令、非法命令不改状态 | `online-response` 测试 |

固定牌局使用真实规则引擎和房间实现，牌和实例 ID 固定。既验证最终 LP、离场和已行动状态，也对照预览；重复提交不扣第二次血，旧版本选择不能复用。

## 每轮浏览器实测

1. 启动 `npm run serve` 与 `npm run serve:online`，打开两个 `http://127.0.0.1:5177/online.html` 页面，用不同名字创建、加入并准备。
2. 优先走本轮新增流程，以及直接关联的取消、失败或重复点击分支。通过页面按钮和卡牌操作，不通过控制台直接调用业务函数或修改牌局来代替点击。
3. 对照另一玩家页面，确认目标、LP、卡牌和回合一致；刷新确认仍是原席位。新增弹窗同时检查桌面与窄屏，按钮不遮挡、无横向溢出。
4. 记录实际动作、预期与结果、控制台错误、截图。新发现的问题若能用纯函数或固定牌局表达，就补进快速回归。

本轮攻击预览验收：直击 1500，LP 3800 → 2300；守备反击 200，我方 LP 4400 → 4200；切换两个目标时预估伤害由 600 变为 100，最终仅结算选中目标。390×844 下确认按钮可见，取消无扣血，重复确认不重复结算。

## 检查范围

### 可重复的陷阱实测

本机单独启动 `node scripts/duel-server.mjs --port=5180 --scenario=trap-response`，双方打开 `http://127.0.0.1:5177/online.html?duelServer=ws%3A%2F%2F127.0.0.1%3A5180%2Fduel`。这只是服务启动参数，客户端不能指定起手牌；仅允许绑定本机地址，正常服务仍随机发牌。

- 1P 起手包含日冕骑士、疾风术士；2P 包含镜光反制、弱化力场、风暴转移、守护刻印。
- 1P 召唤骑士并结束回合；2P 盖放四张陷阱后结束；1P 召唤术士，进入战斗。
- 骑士直击：响应前 LP 保持 4000，1P 不能结束回合；2P 选择弱化力场，最终 LP 2800，骑士 ATK 1200。术士直击后刷新 2P，响应仍存在；放弃后 LP 1600，未发动陷阱仍盖放。
- 下一轮双击镜光反制破坏骑士，不追加伤害；术士直击发动守护刻印，重复确认仍只抽一张且 LP 不变；再下一轮仅剩风暴转移时自动选中，发动后 LP 2000，原攻击取消。
- 不操作响应窗时，15 秒后自动按放弃响应结算且只结算一次；响应中断线会冻结剩余秒数，恢复原席位后继续倒计时。
- 本轮桌面、390×844、844×390 均实际点击通过；响应弹窗无横向溢出，双方浏览器无警告/错误日志。

`npm run smoke:online -- --scenario=trap-response` 连接同一固定场景服务，验证真实 WebSocket 上的盖放隐藏 → 攻击暂停 → 防守方断线重连 → 发动破坏陷阱。CI 已使用此场景；普通 `npm run smoke:online` 仍可验证随机牌局，不再假定起手必然有可召唤怪兽。

当前范围是一次攻击发动一张陷阱；多段连锁和召唤响应尚未覆盖。对手断线时保留响应并冻结倒计时，重连后继续，不会在离线期间静默代替玩家放弃。

### 提交前检查

- 日常小步修改：跑相关 UT 和 `npm run test:online`，实际点击新增交互。
- 提交前：跑一次 `npm test`。变更影响传输或房间服务时再跑 `npm run smoke:online`。
- 规则或人机共用组件变更：补跑关联规则测试及已有浏览器回归场景。
- 所有 UT 已纳入现有 CI 的 `npm test`；不必为每个既有用例重复打开浏览器，也不要用只匹配源码字符串的断言代替行为测试。
