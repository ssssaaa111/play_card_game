# 星魂决斗

一个原创卡牌对战原型，灵感来自动画式卡牌决斗的节奏，但卡名、规则和美术都保持原创。

## 运行

```powershell
cd card-duel
npm run serve
```

然后打开：

```text
http://localhost:5177/
```

本项目固定使用 `5177` 作为本地预览端口；如果端口被占用，先关闭旧服务或直接复用已有页面。

浏览器回归优先点测这些路径：`换位陷阱` 场景盖放 `幻影换位` 后确认连锁提示，`跳攻锁定` 场景验证跳过攻击后新召唤怪兽也不能继续攻击，`直击许可` 场景验证对手有怪兽时不能裸点角色直击。测试模式会暴露只读 `window.__starDuelTest.snapshot()`，方便检查当前回合、场面、连锁弹窗、音频开关和日志审计结果。自动冒烟入口包括 `smoke=skip-lock`、`smoke=direct-guard`、`smoke=combo-spell`、`smoke=ace-attack` 和 `smoke=chain-trap-choice`；关键长链路会同时校验最终日志审计结果，完成后在 `document.body.dataset.smokeStatus` 标记 `passed` 或 `failed`。

需要验证固定结算次数的规则测试场景可以声明 `playerDeck` 或 `aiDeck`，避免随机抽牌、组合技或额外召唤让回归结果漂移。

## 项目结构

- `index.html`：只保留页面 DOM 结构和入口引用。
- `styles.css`：界面布局、卡牌、动画、响应式样式。
- `src/app.js`：当前主流程，包含状态机、渲染、战斗结算、音效和 AI 调度。
- `src/actions.js`：玩家行动窗口模块，统一判断当前是否还能攻击、召唤、盖陷阱、发动魔法或切换表示。
- `src/battle.js`：战斗结算说明模块，统一计算攻击差值、伤害、护盾吸收、破坏结果和战斗损耗。
- `src/browser-smoke.js`：浏览器冒烟测试模块，负责测试模式快照和自动点击回归流程。
- `src/card-detail.js`：卡牌详情文案模块，负责详情面板和放大卡牌的规则说明。
- `src/card-renderer.js`：卡牌 DOM 渲染模块，负责卡面结构、实时数值和状态条。
- `src/cards.js`：卡牌展示元数据，包含稀有度、流派、属性徽标、类型徽标和牌面规则摘要。
- `src/combos.js`：属性组合技规则模块，负责判断火风、光暗、三属性和陷阱联动组合技是否可触发。
- `src/data.js`：纯数据配置，包含卡牌库、怪兽素材映射、角色、卡组预设和规则测试场景。
- `src/deck.js`：卡组和决斗者构造模块，包含卡牌克隆、预设卡组构建和规则测试场景卡组扣除。
- `src/engine-adapter.js`：UI 到核心规则引擎的适配层，负责把固定槽位操作转换成 `GameEngine.dispatch` 事件并回放到界面状态。
- `src/log-audit.js`：日志审计模块，负责从时间线里发现重复日志、关键效果缺少结算日志、攻击预判断链和直击规则矛盾。
- `src/response-state.js`：响应窗口纯状态模块，负责构造、选择和结算可序列化的陷阱响应选择。
- `src/rules.js`：纯规则工具，包含生命上限、场地区数量、攻击/守备数值、直击校验、攻击预览和魔法目标选择规则。
- `src/scenario-state.js`：规则测试场景状态构造模块，统一创建手牌、卡组、怪兽区和陷阱区。
- `src/spells.js`：魔法卡规则模块，包含发动展示文案、目标范围、目标选择规则、发动条件校验和 AI 选牌评分。
- `src/timeline.js`：结算时间线模块，负责把日志文本归类为攻击、召唤、魔法、陷阱、警告等类型。
- `src/traps.js`：陷阱卡规则模块，包含触发事件、触发时机文案和事件匹配。
- `src/turn-state.js`：回合状态机模块，集中管理阶段、行动窗口、玩家可操作状态、暂停恢复和阶段切换 patch。
- `src/view-model.js`：界面文案视图模型，负责把状态转换为回合提示、中心提示和手牌行动说明。
- `assets/`：角色、怪兽和后续音频/美术资源。

后续迭代继续从 `src/app.js` 拆出 `render`、`audio`、`ai` 等模块；浏览器点测相关逻辑已经先拆到 `src/browser-smoke.js`，避免重新堆回单文件。

## 当前玩法

- 双方 4000 生命值，起手 5 张。
- 进入页面后需要点击“开始决斗”，不会自动开局。
- 回合开始会自动抽 1 张，玩家攻击完成且没有可攻击怪兽后会自动结束回合。
- 也可以主动点 `跳过攻击` 放弃本回合剩余攻击机会，或点 `结束回合` 直接放弃后续出牌和攻击；跳过攻击是本回合锁，新召唤怪兽、攻击重置和直击许可都不能绕开。
- 玩家主阶段会显示无操作倒计时；只查看或选中卡牌会重启倒计时，真正发动、召唤、攻击后再按行动窗口重新判断。
- 每回合通常召唤 1 只怪兽，双重召唤可以提供额外通常召唤。
- 对手场上有怪兽时必须先攻击怪兽；只有对手没有怪兽，或 `星隙穿透` 这类卡牌效果授予直接攻击许可时，才能点击对方角色造成直接伤害。
- “连携突击”现在使用攻击重置资源：先攻击再发动会立刻让已攻击怪兽恢复可攻击；先发动再攻击会保留 1 次重置，在下一次攻击结算后自动恢复可攻击。
- 魔法卡会先检查发动条件，例如满血不能回血、没有怪兽不能强化、卡组不足不能发动抽 2。
- 新增破阵、墓地回收、直击和再攻类魔法：`破阵星芒` 会削弱对手怪兽并造成小额伤害，`星尘回收` 会回收墓地资源，`星隙穿透` 会提供 1 次直击许可，`战斗狂热` 会强化怪兽并提供攻击重置。
- 指定目标魔法进入目标选择状态，但会遵守卡牌文本：`战意高扬`、`连携突击`、`战斗狂热` 只能选择我方攻击力最高怪兽，`破阵星芒` 只能选择敌方攻击力最高怪兽。
- 新增属性组合魔法：`炎岚合击` 需要火+风怪兽，`晨昏星界` 需要光+暗怪兽，发动前会先检查场面条件。
- 场上有 3 个怪兽区和 3 个陷阱区。自己的盖放陷阱正面可见，对手陷阱背面隐藏。
- 陷阱满足条件时会触发连锁确认；同一事件可以连续处理多张陷阱，AI 陷阱自动处理。`反击阵列` 会取消攻击并消耗攻击机会，`风暴转移` 会在对手攻击时取消攻击并获得护盾，`星界封锁` 会无效本次攻击，`幻影换位` 会把攻击改到另一只守备力更高的怪兽，发动前会显示当前攻击目标、换位后目标和低 DEF 风险提示，`镜光反制` 会直接破坏攻击怪兽，`弱化力场` 和 `逆焰护壁` 分别用于削弱攻击怪兽和反弹直接攻击。
- 右侧结算时间线按步骤记录抽卡、召唤、魔法、攻击、陷阱连锁和伤害；时间线标题旁会显示日志审计状态，上方战况区只保留最新 1-2 条提示，避免和时间线重复刷屏。
- 攻击前会在卡牌详情区显示结算预览，列出攻击方、目标、差值、护盾吸收和预计生命值伤害。
- 攻击结算日志会明确显示 ATK/DEF 对比、差值、护盾吸收和最终生命值伤害。
- 魔法伤害和回复现在会记录实际结算数值，测试模式快照和时间线状态灯都会附带日志审计结果，帮助发现“不该发生但日志显示发生了”的流程矛盾。
- 攻击会显示箭头、cut-in、怪兽动作、爆炸和伤害结算日志。
- 手牌卡片改为更宽的可读尺寸，直接显示效果说明；卡片右上角会标记当前是否可召唤、可发动、可盖放或条件不足。
- 手牌卡片底部会显示当前操作原因，例如“选中后点击空召唤区”“条件不足”“再次点击即可发动”，减少误点。
- 怪兽卡面现在明确显示 `火属性`、`光属性`、`风属性`、`暗属性`，不再只靠单字图标和颜色猜属性。
- 怪兽被强化、削弱、产生战斗损耗或已经行动时，卡图底部会显示状态条。
- 魔法和陷阱卡面会显示规则摘要，例如指定目标魔法显示 `目标:我方最高`，陷阱显示触发时机和效果摘要。
- 详情面板和放大卡牌会同步显示魔法目标、陷阱触发时机和怪兽当前状态。
- 怪兽没有被破坏但承受冲击时会产生战斗损耗，ATK/DEF 会下降。
- 护盾会优先吸收伤害。

## 本轮基础扩展

- 战斗体验：攻击前增加伤害预判，AI 也会记录自己的攻击预判。
- 卡牌深度：卡牌详情增加稀有度和流派标签。
- 角色系统：开局前可选择星辉使者、炎岚指挥官、辉棱守望者，组合技会触发不同角色技能。
- 卡组编辑器基础版：开局前可选择均衡、速攻、防守三套预设卡组。
- AI 强化：开局前可选择均衡、强攻、防守控场三种 AI 风格。
- 演出升级：保留中场魔法高亮、王牌登场、怪兽投影、攻击特写和箭头演出；高星王牌攻击会额外触发全屏攻势 cut-in。
- 新手引导：规则面板补充扩展系统、战斗损耗、自动回合和陷阱说明。
- 长期玩法：胜负、总局数和连胜会保存到浏览器本地战绩。
- 规则测试：开局前可选择连锁测试、组合魔法、王牌攻势、直击许可、换位陷阱、目标选择等固定场景，便于快速验证新增机制。
- 规则测试场景会在场地中央和时间线里显示测试目标，告诉玩家下一步该操作什么。

## 机制设计

- 回合主状态：`setup`、`draw`、`main`、`autoEnd`、`ai`、`gameOver`。
- 回合阶段和行动窗口的核心判断集中在 `src/turn-state.js`：`canPlayerActState` 判断玩家是否可操作，`playerActionWindowDecision` 决定行动后留在主阶段还是进入自动结束，`turnStartPatch` 和 `drawToMainPatch` 负责阶段切换字段。
- 攻击预判到最终伤害日志之间使用不可操作的 `resolution` 行动窗口；结算完成后才重新开放 `battle`，避免玩家把盖牌或结束回合插入攻击结算中间。
- 玩家点击、选牌、召唤、盖陷阱、发动魔法都会取消待执行的自动结束定时器。
- 每次行动结算后会重新评估行动窗口：还有可攻击怪兽、可发动魔法、可召唤怪兽、可盖陷阱或可切换表示时，继续留在玩家主阶段；没有行动时才进入自动结束。
- 玩家可以手动跳过攻击或结束回合；手动结束会取消当前目标选择并直接交给 AI。跳过攻击设置 `attacksSkipped` 本回合标记，攻击窗口、直接攻击许可和攻击重置都必须尊重这个标记。
- 倒计时只在玩家主阶段、非目标选择、非自动结束状态下运行；被动查看卡牌或选中怪兽后必须恢复倒计时，避免清掉计时器后停住。
- 切换攻击 / 守备表示也会立即重新评估行动窗口；如果切到守备后没有其他可操作项，会自动进入回合结束倒计时。
- 卡牌效果尽量落到资源和标记上，例如额外召唤使用 `extraSummon`，攻击重置使用 `attackResets`，怪兽本回合攻击状态使用 `used`。
- `双重召唤` 会通过 `ABILITY_GRANTED` 授予额外召唤许可，并回放成 UI 的 `extraSummon` 资源，后续召唤消耗该资源。
- `战斗狂热` 会通过 `STAT_MODIFIED` 强化我方最高攻击怪兽，并通过 `ABILITY_GRANTED` 授予 1 次攻击重置。
- `星盾展开` 会通过 `SHIELD_GAINED` 获得护盾，并由事件统一处理 2400 护盾上限。
- `星尘回收` 会通过 `CARD_MOVED` 把墓地目标放回卡组顶，再通过 `CARDS_DRAWN` 抽回手牌，UI 只按事件回放移动和抽卡。
- 直接攻击使用统一校验：`validateAttackTarget` 会拦截非法直击，玩家点对方角色时使用 `-1` 作为直击目标，`星隙穿透` 会通过 `ABILITY_GRANTED` 授予直击许可，并回放成 UI 的 `directAttacks` 资源，结算直击后自动消耗。
- 目标选择使用 `pendingTarget` 和 `targetSelect` 行动窗口：发动指定目标魔法后先高亮合法目标，点击合法怪兽后才移动卡牌并结算效果。
- 魔法效果统一挂在 `spellEffects` 注册表里，每个效果包含发动条件、实际结算、演出文案和 AI 评分，避免继续堆硬编码分支。
- 盖放陷阱已通过 `GameEngine.dispatch({ type: "SET_TRAP" })` 校验并产出 `CARD_MOVED/TRAP_SET` 事件，UI 只按事件回放固定槽位变化。
- 召唤怪兽已通过 `GameEngine.dispatch({ type: "SUMMON_MONSTER" })` 校验并产出 `CARD_MOVED/MONSTER_SUMMONED` 事件，UI 只按事件回放手牌到怪兽区的移动和召唤状态标记。
- 抽卡、回血、护盾、墓地回收、单体强化、攻击重置、基础伤害、指定目标削弱伤害、直击许可和额外召唤魔法已通过 `GameEngine.dispatch({ type: "ACTIVATE_CARD" })` 产出 `CARD_MOVED/CARDS_DRAWN/LP_HEALED/SHIELD_GAINED/STAT_MODIFIED/DAMAGE_DEALT/ABILITY_GRANTED` 事件；伤害事件会记录 `requested/blocked/amount`，由事件回放统一处理护盾吸收和最终扣血。
- 陷阱触发拆成 `trapCanResolve` 和 `resolveTrapCard`，`triggerTrap` 会按当前场面逐张处理同一事件上的连锁结果。
- `state.timeline` 从日志事件派生结算时间线，后续可以逐步替换成更正式的事件流。
- 后续新增卡时优先按“发动条件校验 -> 支付/移动卡牌 -> 效果资源/数值结算 -> 重新评估行动窗口”的顺序实现。
